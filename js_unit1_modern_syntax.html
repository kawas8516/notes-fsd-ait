1. Introduction to JavaScript and the Execution Environment

JavaScript is a high‑level, interpreted (just‑in‑time compiled), single‑threaded, dynamically‑typed programming language. The core language is standardised as ECMAScript; every place JS actually runs — a browser, Node.js — is a host environment that plugs extra objects into that core (the browser adds window, the DOM, fetch; Node adds fs, process, etc.).[1]

Statements and comments

A JavaScript program is a sequence of statements — complete instructions such as a declaration, an assignment, or a function call, conventionally ended with a semicolon (JS also has Automatic Semicolon Insertion, which inserts missing semicolons for you in most cases, but relying on it can cause subtle bugs).

// A single-line comment
let x = 5; // statement: declare and initialise a variable

/* A multi-line comment
   can span several lines */
console.log(x); // statement: function call

Execution context and the call stack

When a script starts, the engine creates a Global Execution Context. Every function call creates its own execution context, which is pushed onto the call stack; when the function returns, its context is popped off. Each context is built in two phases: a creation phase (memory is allocated for variables/functions — this is what causes hoisting) and an execution phase (code actually runs line by line).

The event loop — how single-threaded JS handles async work

JavaScript has exactly one call stack, so it can only do one thing at a time. Asynchronous behaviour (timers, network requests, DOM events) is possible because the host environment provides Web APIs that run outside the call stack; when they finish, their callback is placed in a queue, and the event loop continuously checks: "is the call stack empty? If so, move the next queued callback onto it."[2]

Fig. 1 — The event loop only moves a callback onto the call stack once the stack is completely empty, which is why a setTimeout(fn, 0) still runs after all currently‑running synchronous code.
console 
console.log('1: start');
setTimeout(() => console.log('2: from setTimeout'), 0);
console.log('3: end');

// Output order: 1: start → 3: end → 2: from setTimeout
// setTimeout's callback waits for the call stack to empty first,
// even with a 0ms delay.
Key point: JavaScript itself is single‑threaded — the concurrency you see (timers, network calls, UI responsiveness) comes from the host environment's APIs plus the event loop, not from JS running multiple things literally at once.

2. Variables — var, let, and const

JavaScript has three variable declaration keywords, introduced at different points in the language's history, with different scoping and hoisting rules.[3]

ScopeFunction-scopedBlock-scoped ({ })Block-scoped

Re-declarationAllowedNot allowed in the same scopeNot allowed
Re-assignmentAllowedAllowedNot allowed (the binding is constant)

Fig. 2 — var ignores block boundaries (only function boundaries stop it); let/const respect every { } block.
console.log(typeof x); // "undefined" — var is hoisted & pre-initialised
var x = 10;

console.log(typeof y); // ReferenceError — y is in the Temporal Dead Zone
let y = 20;

const PI = 3.14159;
PI = 3;        // TypeError: Assignment to constant variable.

const person = { name: 'Ada' };
person.name = 'Grace';   // OK — the object's contents are still mutable,
                          // only the *binding* `person` itself is constant.
Common pitfall: const does not make an object or array immutable — it only prevents the variable from being reassigned to a different value. Use Object.freeze() if true immutability is required.

Modern best practice: default to const; use let only when a variable must be reassigned (loop counters, accumulators); avoid var in new code.

Type conversion (coercion)

Implicit conversion happens automatically when operators are used across mismatched types; explicit conversion is done deliberately with functions like Number(), String(), Boolean(), or parseInt().

// Implicit (coercion)
'5' + 3        // "53"  → number 3 is coerced to a string, then concatenated
'5' - 3        // 2     → string '5' is coerced to a number for subtraction
true + 1       // 2     → true coerces to 1

// Explicit
Number('42')   // 42
String(42)     // "42"
Boolean('')    // false  (empty string is "falsy")
Boolean('0')   // true   (a non-empty string is always "truthy")
== (loose equality)=== (strict equality)
Coerces operands to the same type before comparingCompares both value and type, no coercion
'5' == 5 → true'5' === 5 → false
null == undefined → truenull === undefined → false
Best practice: always prefer ===/!== over ==/!= — it avoids the surprising coercion rules and makes bugs far less likely.

let count = 0;
console.log(count || 10);   // 10 — 0 is falsy, so || falls through
console.log(count ?? 10);   // 0  — 0 is not null/undefined, so ?? keeps it

const user = { profile: null };

Common pitfall: || falls back on any falsy value (0, '', NaN, false), which is usually not what you want for numeric defaults — ?? is the safer choice when the goal is specifically "handle missing/null values."

5. Arrays

An array is an ordered, zero-indexed, resizable list that can hold mixed types.

Fig. 4 — Indexing always starts at 0; fruits.length is 4, and fruits[4] is undefined.

const prices = [10, 25, 40, 55];

const withTax = prices.map(p => p * 1.18);      // [11.8, 29.5, 47.2, 64.9]
const expensive = prices.filter(p => p > 20);    // [25, 40, 55]
const total = prices.reduce((sum, p) => sum + p, 0); // 130
Key point: map/filter/reduce never modify the original array — they return a new one, which makes code easier to reason about and is central to a functional, predictable coding style.

Fig. 5 — Every counting loop follows this same init → check → body → update → recheck cycle, whichever keyword is used.
const nums = [10, 20, 30];

for (let i = 0; i < nums.length; i++) console.log(i, nums[i]);
for (const n of nums) console.log(n);              // values: 10, 20, 30

const obj = { a: 1, b: 2 };
for (const key in obj) console.log(key, obj[key]);  // keys: a, b
Common pitfall: using for...in on an array works but is discouraged — it iterates keys (as strings, including any inherited enumerable properties) rather than guaranteeing numeric order; use for...of or array methods on arrays instead.

8. Functions — Declarations and Arrow Functions

AspectFunction DeclarationArrow Function
Syntaxfunction greet() {}const greet = () => {}
HoistingFully hoisted — callable before its definitionNot hoisted (it's a variable holding a function)
this bindingDynamic — determined by how the function is calledLexical — inherits this from the surrounding scope
Own arguments objectYesNo
Usable as a constructor (new)YesNo
Best forObject methods, constructors, when dynamic this is wantedCallbacks, array methods, preserving outer this
const user = {
  name: 'Ada',
  greetRegular: function () {
    console.log(this.name);           // "Ada" — `this` = the object it's called on
  },
  greetArrow: () => {
    console.log(this.name);           // undefined — arrow has no own `this`;
  }                                    // it uses `this` from where it was DEFINED
};

user.greetRegular(); // "Ada"
user.greetArrow();   // undefined

This is why arrow functions are so useful inside callbacks that need to keep the outer this:

class Timer {
  seconds = 0;
  start() {
    setInterval(() => {
      this.seconds++;   // arrow function keeps `this` = the Timer instance
    }, 1000);
  }
}

Function declaration vs. function expression

A declaration (function foo() {}) is hoisted with its full body. A function expression (const foo = function () {}, including arrow functions) is only hoisted as a variable — calling it before the assignment line throws (or gives undefined for var).

9. Objects and Methods

An object is an unordered collection of key–value pairs ("properties"). A property whose value is a function is called a method.

const car = {
  brand: 'Toyota',
  model: 'Corolla',
  year: 2024,
  start() {                       // ES6 method shorthand
    console.log(`${this.brand} is starting...`);
  }
};

console.log(car.brand);           // dot notation
console.log(car['model']);        // bracket notation (needed for dynamic keys)
car.start();                      // "Toyota is starting..."

car.color = 'red';                // add a new property
delete car.year;                  // remove a property

console.log(Object.keys(car));    // ['brand', 'model', 'start', 'color']
console.log(Object.values(car));
console.log(Object.entries(car)); // [['brand','Toyota'], ...] — key/value pairs
Key point: inside a regular method, this refers to "the object the method was called on" — car.start() sets this to car. Calling the same function without an object context (e.g. assigning it to a plain variable and calling it) loses that binding.

10. ES6+ Features: Destructuring, Template Literals, Spread & Rest

Destructuring — unpacking values into variables

Fig. 6 — const { name, age } = user; pulls two matching properties straight into two new variables in one line.
// Object destructuring
const user = { name: 'Ada', age: 30, country: 'UK' };
const { name, age } = user;               // name = 'Ada', age = 30
const { name: n, country: c = 'N/A' } = user; // rename + default value

// Array destructuring
const coords = [10, 20, 30];
const [x, y] = coords;                    // x = 10, y = 20
const [, , z] = coords;                   // skip elements: z = 30

Spread (...) vs. Rest (...)

The same three dots mean opposite things depending on context: spread expands an iterable into individual elements; rest collects multiple individual items back into a single array.

Fig. 7 — Spread (top) unpacks a collection outward; rest (bottom) gathers loose items back into one array — opposite directions, same ... syntax.
// Spread — expand
const a = [1, 2, 3];
const b = [...a, 4, 5];          // [1, 2, 3, 4, 5] — non-mutating copy + extend
const merged = { ...user, age: 31 }; // shallow-copy an object, override one field
console.log(Math.max(...a));      // spreads array into separate function arguments

// Rest — collect
function sum(...numbers) {        // numbers = [1, 2, 3, 4] however many are passed
  return numbers.reduce((t, n) => t + n, 0);
}
sum(1, 2, 3, 4);                  // 10

const [first, ...rest] = [1, 2, 3, 4]; // first = 1, rest = [2, 3, 4]
