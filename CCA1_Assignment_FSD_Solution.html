Q1. What is the DOM? 5 Marks

Definition. The Document Object Model (DOM) is a programming interface (API) for HTML and XML documents. It represents a document as a logical, language‑independent tree of objects/nodes in memory, so that programs such as JavaScript can read, add, remove, or change the document's structure, content, and style while the page is running — without reloading it.[1]

How a browser turns HTML into a DOM tree

  1. Tokenizing: the HTML parser scans the raw HTML text and breaks it into tokens (start tags, end tags, text, attributes).
  2. Tree construction: tokens are converted into node objects and connected according to how tags were nested in the source.
  3. Root assignment: the finished tree is attached to the special document object, which JavaScript accesses as window.document.

Node types that make up the tree

Node typeRepresentsExample
Document nodeThe root of the whole treedocument
Element nodeAn HTML tag<h1>, <div>
Text nodeThe literal text inside an element"Hello"
Attribute nodeA tag's attributeclass="title"
Comment nodeAn HTML comment<!-- note -->

Example

index.html 
<!DOCTYPE html>
<html>
  <body>
    <h1>Hello</h1>
  </body>
</html>
Fig. 1 — Every nested tag becomes a child node; the visible text becomes its own text‑node leaf.
Key point: the DOM is not the HTML file — it is the browser's live, in‑memory tree. JavaScript reads/writes this tree (e.g. document.querySelector(), appendChild()), and the browser re‑renders the screen to match it.

Q2. DOM Tree for html, head, body, h1, p, div 5 Marks

Consider the following HTML document:

index.html 
<!DOCTYPE html>
<html>
  <head>
    <title>Sample Page</title>
  </head>
  <body>
    <h1>Welcome</h1>
    <p>This is a paragraph.</p>
    <div>This is a div.</div>
  </body>
</html>
Fig. 2 — html is the root; head and body are siblings; title is head's only child; h1, p, div are siblings under body.

Parent‑child relationships

  • html is the root element — parent of head and body.
  • head and body are siblings (same parent, html).
  • title is the only child of head.
  • h1, p, and div are all children of body, and therefore siblings of one another.
  • Each of title, h1, p, and div additionally owns one text node child holding its visible text (omitted above for clarity).

Q3. How ReactJS Uses JSX 5 Marks

JSX (JavaScript XML) is a syntax extension that lets developers write HTML‑like markup directly inside JavaScript. Browsers cannot run JSX natively, so a compiler (Babel, part of every React toolchain) transpiles each JSX tag into a call to React.createElement() — or, with the modern automatic JSX runtime, into an internal _jsx() call.[3]

Every one of these calls returns a plain JavaScript object called a React element — a lightweight description of "what should appear on screen", not an actual DOM node. React later reads this tree of elements and builds/updates the real DOM to match it.

JSX code example

Greeting.jsx 
function Greeting() {
  return (
    <div className="greeting">
      <h1>Hello, World!</h1>
      <p>Welcome to React.</p>
    </div>
  );
}

Babel transpiles this to (classic runtime, shown for teaching clarity):

function Greeting() {
  return React.createElement(
    "div",
    { className: "greeting" },
    React.createElement("h1", null, "Hello, World!"),
    React.createElement("p", null, "Welcome to React.")
  );
}

...which produces this React element object at runtime:

{
  type: "div",
  props: {
    className: "greeting",
    children: [
      { type: "h1", props: { children: "Hello, World!" } },
      { type: "p",  props: { children: "Welcome to React." } }
    ]
  }
}

Finally, this element tree is mounted to a real DOM node:

import { createRoot } from "react-dom/client";
createRoot(document.getElementById("root")).render(<Greeting />);
Key point: JSX → createElement calls → React element tree → ReactDOM walks the tree and creates/updates real DOM nodes. JSX is purely syntax sugar for describing UI structure declaratively.

Q4. DOM Tree of Nested JSX Elements 5 Marks

Consider a component tree made of a parent App composed of three child components, Header, Main, and Footer:

App.jsx 
function Header() {
  return (
    <header>
      <h1>My Website</h1>
    </header>
  );
}

function Main() {
  return (
    <main>
      <p>Welcome to the homepage.</p>
      <ul>
        <li>Home</li>
        <li>About</li>
      </ul>
    </main>
  );
}

function Footer() {
  return (
    <footer>
      <p>&copy; 2026</p>
    </footer>
  );
}

function App() {
  return (
    <div className="app">
      <Header />
      <Main />
      <Footer />
    </div>
  );
}

React first resolves the component tree (App → Header, Main, Footer) by calling each function. Custom components (capitalized, e.g. <Header />) are not real tags — React "unwraps" them and keeps only the host elements (lowercase tags like div, header, p) they eventually return. Only those host elements become actual nodes in the browser's DOM:

Fig. 3 — Actual rendered DOM tree. Note Header, Main, Footer do not appear as nodes — only the host tags they returned do.

Parent‑child relationships

  • div.app is the root and direct parent of header, main, and footer (siblings).
  • h1 is the sole child of header.
  • p ("Welcome…") and ul are children of main, hence siblings.
  • li "Home" and li "About" are children of ul, and grandchildren of main.
  • p ("© 2026") is the sole child of footer.

Q5. DOM vs Virtual DOM 5 Marks

AspectReal DOMVirtual DOM
What it isThe browser's actual, live tree that is painted on screenA lightweight, in‑memory JavaScript object tree that mirrors the UI[4]
Update costExpensive — every mutation can trigger layout recalculation (reflow) and repaintCheap — creating/comparing plain JS objects has no rendering cost
Update strategyDirect, immediate mutation, one change at a timeBatched — React first computes a "diff" against the previous tree, then applies only the minimal real changes
Managed byThe browser engineReact's reconciler (built on the Fiber architecture since React 16)[5]
Performance at scaleDegrades with many frequent direct editsStays fast — many small state changes are combined into one efficient DOM update

Why React uses this approach (reconciliation)

  1. A state/props change causes React to build a new element tree describing the desired UI.
  2. React diffs this new tree against the previous one to find exactly what changed.
  3. React computes the minimal set of real DOM operations required.
  4. The Fiber engine applies these updates to the real DOM, batching work and even splitting it into interruptible units for smoother performance.
Key point: Writing to the real DOM directly for every small change is slow because the browser must recompute layout and repaint. By diffing lightweight JS objects first and touching the real DOM only where necessary, React lets developers write simple, declarative code ("render UI for this state") while still getting fast updates. Note: current official React docs favour describing this as "the reconciler/Fiber" rather than the term "virtual DOM", but the underlying diff‑then‑patch idea is the same.

Q6. React App — Heading, Paragraph, List, Button 5 Marks

App.jsx 
function App() {
  return (
    <div className="app">
      <h1>Welcome to My React App</h1>
      <p>This is a simple ReactJS application demonstrating a heading,
         a paragraph, a list, and a button.</p>
      <ul>
        <li>Learn HTML</li>
        <li>Learn CSS</li>
        <li>Learn JavaScript</li>
        <li>Learn ReactJS</li>
      </ul>
      <button onClick={() => alert("Button clicked!")}>Click Me</button>
    </div>
  );
}

export default App;
main.jsx 
import { createRoot } from "react-dom/client";
import App from "./App";

createRoot(document.getElementById("root")).render(<App />);

ul / li×4Bulleted list: Learn HTML, Learn CSS, Learn JavaScript, Learn ReactJS
